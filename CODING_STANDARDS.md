# Coding Standards

> Covers architecture, runtime invariants, capability boundaries, security/operational governance, and judgement calls across Frontend and GAS Backend.
> Formatting, import ordering, and basic syntax/type checks are enforced by Prettier, ESLint, and `tsc` — do not duplicate them in reviews.

## Capability Tiers

Adopt capabilities pragmatically — keep the Base Template lean with **zero Optional libraries pre-installed**, and add Optional or Project-Specific capabilities only when required by an approved spec.

### Core (Pre-Installed & Required)

- **Core Stack & Runtime (ADR-0001, ADR-0005):** React 19, Vite 7, TypeScript Strict, Tailwind CSS v4, TanStack Query v5, and Google Apps Script (TypeScript + `esbuild` + `@google/clasp` v3) in a lean two-workspace monorepo (`frontend/` and `backend/`), pinned strictly to **Node.js 26 Active LTS** and **npm 11** across `.nvmrc`, `package.json` (`engines`, `packageManager`), and GitHub Actions CI.
- **Engineering Quality Baseline (ADR-0004, ADR-0005, ADR-0006):** ESLint (splitting GAS runtime sources from Node.js scripts in `backend/eslint.config.js`), Prettier, Vitest (frontend component & API client seams, backend pure + `doGet`/`doPost` in-memory GAS integration, cross-workspace API contract tests, offline tooling tests), dev-only Vite mock middleware sharing plain `Item` fixtures (`tests/fixtures/items.ts`), automated Playwright E2E + responsive + `@axe-core/playwright` WCAG 2.2 AA scans (`npm run test:e2e`), offline GAS bundle verification (`npm run verify:gas-bundle`), offline GitHub Actions CI merge gates (`quality` → `e2e`), Dependabot Alerts/Security Updates/weekly grouped PRs, and guarded Staging/Production `clasp -P` immutable versioned deployments.
- **Security & Data Integrity Baseline (ADR-0002, ADR-0003):** Explicit `SPREADSHEET_ID` from Script Properties (`CONFIG_MISSING`, no `getActiveSpreadsheet()` fallback), fail-closed GAS Web App manifest (`executeAs: "USER_DEPLOYING"`, `access: "MYSELF"`, explicit least-privilege `oauthScopes`), mandatory pre-deploy Security Review and server-side token verification before `ANYONE_ANONYMOUS`, strict input validation, formula injection neutralization (`=`, `+`, `-`, `@`, `\t`, `\r`), `@` plain-text formatting for all text columns, read-only `doGet`, `LockService` + `SpreadsheetApp.flush()` + `finally` unlock, structured JSON logging without secrets/PII/Spreadsheet IDs, generic `INTERNAL_ERROR` responses, UI in-flight submission disabling, and `mutations.retry: 0`.
- **Core AI Tooling (Multi-Agent SSOT — ADR-0007):** `AGENTS.md` + plain-text `CLAUDE.md` (`@AGENTS.md`), `.agents/skills/` pinned via `skills-lock.json` (12 Matt Pocock workflow skills configured for GitHub Issues, `ui-ux-pro-max` for design systems with `python3` required **solely** for its local `scripts/search.py` and never for application runtime/build/CI, Vercel `web-design-guidelines` for offline UI/accessibility audits, and `playwright-cli`), secret-free MCP parity (`.mcp.json` / `.codex/config.toml` + manual Antigravity guidance) for **Context7 MCP** and **Playwright MCP** (choose Playwright CLI **or** Playwright MCP per session — never both), plus `skills:sync`, non-destructive `agents:setup`, and offline `agents:check`.

### Project-Specific (Driven Strictly by Business Requirements)

- **Authentication / Authorization:** Never shipped as hardcoded or placeholder auth in the Base Template (ADR-0003). Implement per-project authentication (e.g., Google Identity, OIDC, signed JWT) with mandatory backend token verification and role/action authorization before exposing `ANYONE_ANONYMOUS`.
- **Domain & External Integrations:** Business-specific third-party APIs, notifications, additional least-privilege Google Workspace OAuth scopes (Drive, Gmail, Calendar), and custom workflows driven by approved specs.

## 1. Monorepo & API Boundaries (Hard Violations)

- **[ARCH-1] Strict Workspace & Runtime Separation:** `frontend/` must never import GAS globals or `backend/` runtime code; `backend/` must never depend on DOM, browser APIs, or React modules. Within `backend/`, `eslint.config.js` must keep GAS runtime sources (`src/**/*.ts`, excluding `src/**/*.test.ts`) free of Node.js globals and `node:*` imports while permitting Node.js globals only in test files (`src/**/*.test.ts`, `test/**/*.ts`), `eslint.config.js`, and build/verification scripts (`*.mjs`, ADR-0005).
- **[ARCH-2] Single Frontend API Client:** React components must not call `fetch` directly against GAS Web App URLs. Route all requests through `frontend/src/api/gasClient.ts`, which encapsulates endpoint URLs, payload serialization, and error normalization.
- **[ARCH-3] Decoupled GAS Domain Logic:** Keep pure transformation, schema mapping, and validation logic in dedicated modules (`backend/src/sheetsLogic.ts`, etc.) separate from `SpreadsheetApp`, `LockService`, and `PropertiesService` calls in `backend/src/main.ts` so core backend rules remain unit-testable offline in Vitest while sharing the exact same code bundled into `backend/dist/Code.js` for `@google/clasp`.
- **[ARCH-4] No Speculative Abstraction:** Keep the repository to two workspaces (`frontend/` and `backend/`, ADR-0001). Do not introduce a shared contracts workspace, generic wrappers, or factories until at least two distinct real use cases require them.

## 2. Frontend: React, TypeScript, TanStack Query & Tailwind (Conventions)

- **[FE-1] No `useEffect` + `fetch`:** Never fetch or mutate server data inside `useEffect`. Route all server state through TanStack Query (`useQuery`, `useMutation`) hooks wrapping `gasClient`.
- **[FE-2] GAS-Friendly QueryClient Defaults & Selective Retries:** Keep `refetchOnWindowFocus: false`, `staleTime: 5 * 60 * 1000`, selective query retries (at most 1 retry strictly on transient errors: `TIMEOUT`, `NETWORK_ERROR`, `LOCK_TIMEOUT`, and HTTP `429`/`5xx`; never retry `ABORTED` or validation/config/contract errors), and `mutations.retry: 0` to respect GAS execution quotas, tolerate cold starts, and prevent duplicate writes.
- **[FE-3] Validate & Classify at the API Boundary:** Enforce a configurable request timeout (default `20_000` ms) with `AbortController` while forwarding caller/TanStack Query `AbortSignal` (`TIMEOUT` vs `ABORTED`), support both absolute GAS URLs and relative local paths, classify HTTP 200 HTML/non-JSON responses as typed `NON_JSON_RESPONSE` errors, treat raw JSON returned by GAS as `unknown`, and validate the `{ ok: true, data }` / `{ ok: false, error }` envelope before entering UI state (`TIMEOUT`, `ABORTED`, `NETWORK_ERROR`, `HTTP_ERROR`, `NON_JSON_RESPONSE`, `INVALID_ENVELOPE`, `INVALID_DATA`). Do not use blind type assertions (`as SomeType`) on unvalidated network responses.
- **[FE-4] Derive State Instead of Syncing:** Compute derived values during render rather than storing duplicate state synchronized via `useEffect`.
- **[FE-5] Explicit Async States, WCAG 2.2 AA Baseline & Routing:** Every GAS-backed view must handle loading, empty, and error states explicitly using accessible live regions (`role="status"` / `aria-busy` for loading, `role="alert"` for load/validation/mutation errors), explicit `<label>` associations for form inputs, clear visible focus indicators (never remove focus outlines without a high-contrast replacement), and in-flight submission disabling to prevent duplicate writes. Automated `@axe-core/playwright` scans are a minimum WCAG 2.2 AA gate only and never replace manual keyboard, focus, and semantic accessibility checks. When a spec requires multiple pages/routes, install and use `react-router` instead of ad-hoc state switching.

## 3. Backend: Google Apps Script & Sheets (Hard Violations)

- **[GAS-1] Batch Sheet I/O Only:** Never call `getValue()`, `setValue()`, or `appendRow()` inside a loop. Always read/write ranges in bulk with `getValues()` and `setValues()`.
- **[GAS-2] Preserve String Columns & Leading Zeros:** Codes/IDs with leading zeros (e.g., `054`, `00123`, phone numbers) and all `Item` text columns (`id`, `code`, `name`, `createdAt`) must remain `string` end-to-end across Frontend, API DTOs, and Sheets. On write (`backend/src/main.ts`), always apply `.setNumberFormat("@")` to all target text columns **before** batch `.setValues()`. On read (`backend/src/sheetsLogic.ts`), filter blank rows, normalize `Date` cells to ISO-8601 strings, and preserve string values without coercing leading-zero codes to `number`.
- **[GAS-3] Lock Concurrent Writes & Keep Reads Read-Only:** Keep `doGet` strictly read-only (zero sheet mutations; return `[]` if the sheet or data rows do not yet exist, and `SCHEMA_ERROR` if headers are invalid). Wrap all `doPost` sheet initialization and batch writes in `LockService.getScriptLock()` with a bounded `tryLock()` timeout, call `SpreadsheetApp.flush()` after writes, and always execute `lock.releaseLock()` in a `finally` block even if `flush()` throws (ADR-0002).
- **[GAS-4] Centralized Column Schema:** Resolve columns via header mapping or a single schema definition rather than scattering hardcoded numeric column indices across handlers.
- **[GAS-5] `ContentService`, Canonical Error Envelope & Structured Logging:** Use `doGet` / `doPost` with `ContentService.createTextOutput(...).setMimeType(ContentService.MimeType.JSON)`. Per Google Official Documentation, `ContentService` cannot set custom HTTP status codes (e.g., `400`, `401`, `404`) or custom response headers, and Google redirects `/exec` via HTTP `302` to `script.googleusercontent.com` (clients must follow redirects). Every path must return `{ ok: true, data }` or `{ ok: false, error: { code, message } }` using canonical server error codes (`CONFIG_MISSING`, `SCHEMA_ERROR`, `INVALID_JSON`, `INVALID_ACTION`, `VALIDATION_ERROR`, `LOCK_TIMEOUT`, `INTERNAL_ERROR`). Record unexpected errors server-side via structured JSON `console` logs (excluding secrets, tokens, PII, and raw Spreadsheet IDs) and return a safe generic `INTERNAL_ERROR` message to clients without leaking raw exception details.
- **[GAS-6] GAS Quotas (Pragmatic):** Respect official [Google Apps Script Quotas](https://developers.google.com/apps-script/guides/services/quotas) (6 min/execution standard runtime, 30 simultaneous executions/user, 1,000/script, and daily service quotas) via batch Sheets I/O (`[GAS-1]`) and TanStack Query defaults (`[FE-2]`). Do not build complex quota-management, queueing, or rate-limiter systems upfront unless an approved spec requires them.

## 4. Security, Idempotency & Dependency Governance (Hard Violations)

- **[SEC-1] Validate Backend Inputs:** Enforce strict string types, trimming, non-empty checks, bounded field lengths, allowed actions, and bounded payload/batch limits in `doGet`/`doPost` before touching any Sheet range.
- **[SEC-2] Explicit `SPREADSHEET_ID` & No Hardcoded Secrets:** Resolve `SPREADSHEET_ID` strictly from `PropertiesService.getScriptProperties()` and fail closed with `CONFIG_MISSING` when unset (never fall back to `SpreadsheetApp.getActiveSpreadsheet()`, ADR-0002). Read frontend endpoint URLs from `import.meta.env.VITE_GAS_API_URL`, and never commit `.env*`, `.clasp*.json`, `.clasprc.json`, Spreadsheet IDs, or tokens.
- **[SEC-3] Guard Against Formula Injection:** Sanitize user-supplied strings starting with `=`, `+`, `-`, `@`, `\t`, or `\r` (e.g., prefixing `'` or rejecting per spec) before writing them into Google Sheets cells.
- **[SEC-4] Fail-Closed GAS Manifest & Mandatory Backend Auth Policy (ADR-0003):** Keep `backend/appsscript.json` fail-closed (`executeAs: "USER_DEPLOYING"`, `access: "MYSELF"`, explicit least-privilege `oauthScopes: ["https://www.googleapis.com/auth/spreadsheets"]`). Before any downstream deployment switches `webapp.access` to `"ANYONE_ANONYMOUS"`, complete a documented Security Review and implement real server-side token verification (cryptographic signature, issuer `iss`, audience `aud`, and expiration `exp`) plus action/role authorization before reading non-public data or performing writes. Send tokens strictly in the `POST` body — never in URL query parameters, never as static `VITE_*` frontend variables, and never in custom `Authorization` headers that trigger unsupported GAS CORS preflight requests.
- **[SEC-5] Idempotency & Duplicate-Write Protection:** Core enforces UI in-flight submission disabling (`[FE-5]`) and `mutations.retry: 0` (`[FE-2]`). Downstream projects performing transactional, financial, inventory, or non-duplicable writes **must** implement server-side idempotency by verifying a caller-supplied `requestId` inside `LockService.getScriptLock()` against a durable key stored in Google Sheets (never relying on volatile `CacheService` alone).
- **[SEC-6] Runtime Pinning & Vulnerability Triage Policy (ADR-0005):** Keep `.nvmrc`, `package.json` (`engines`, `packageManager`), and `.github/workflows/ci.yml` synchronized strictly on Node.js 26 Active LTS and npm 11. Manage dependency vulnerabilities via GitHub Dependabot Alerts, Dependabot Security Updates, and weekly grouped PRs (`.github/dependabot.yml`) instead of a brittle `npm audit` CI hard blocker: triage Critical/High production dependencies within **48 hours**, Critical/High dev/CI tooling within **7 days**, and Moderate/Low in weekly grouped maintenance PRs (tracking unpatched upstream advisories in GitHub Issues).

## 5. Testing & Seams (Conventions)

- **[TEST-1] Test Behavior at Seams:** Write Vitest tests against public component behavior, API client & QueryClient contracts, backend `doGet`/`doPost` entrypoints, pure GAS transform functions, cross-workspace API contract tests (`tests/contract/api.contract.test.ts`) linking frontend `gasClient` directly to backend `doGet`/`doPost` in memory, and offline CLI/filesystem tooling guards (`scripts/**/*.test.mjs`, `backend/*.test.mjs`). Do not assert on Tailwind utility class names or internal hook implementation details.
- **[TEST-2] Isolated & Deterministic:** Mock network boundaries (`fetch`) in frontend tests and pass fake clocks/IDs where needed; automated tests must never hit a live GAS deployment, real Google Sheet, or external network.
- **[TEST-3] Automated Playwright E2E vs. Interactive Browser QA (ADR-0004):** Keep automated E2E regression tests separate from interactive Browser QA sessions:
  - **Automated Playwright E2E (Core — `npm run test:e2e`, included in `npm run verify`):** Run `@playwright/test` + `@axe-core/playwright` offline against the built production frontend bundle served via `vite preview` (`frontend/dist/`), intercepting only the HTTP network boundary (`page.route()`) using plain shared `Item` fixtures (`tests/fixtures/items.ts`) without introducing a mock framework. Cover core CRUD flows, leading-zero preservation (`00123`), client/server validation errors, HTTP 200 HTML (`NON_JSON_RESPONSE`) handling, desktop/mobile responsive layouts, production-bundle exclusion of dev mock middleware, and automated WCAG 2.2 AA Axe scans. Passing Axe alone is a minimum automated gate and does **not** equal full WCAG 2.2 AA compliance (manual keyboard, focus, and semantic checks remain required).
  - **Dev-Only Offline Mock API:** During local development and interactive QA (`npm run dev`), `frontend/dev/mockGasMiddleware.ts` (`apply: 'serve'`) serves `/api/gas` from the same plain fixtures in `tests/fixtures/items.ts` when `VITE_GAS_API_URL` is unset or set to `/api/gas`. This middleware must remain strictly dev-only and never be bundled into `frontend/dist/`.
  - **Interactive Browser QA (Playwright CLI / MCP):** Use either Playwright CLI (`npx playwright-cli`, preferred for token efficiency) or Playwright MCP (`.mcp.json` / `.codex/config.toml` / Antigravity MCP config) — never both simultaneously.
    - **Base Template (Offline / Unconnected):** Verify the template using `npm ci` and `npm run verify` (`check` → `build` → `verify:gas-bundle` → `test:e2e`), and run interactive Playwright QA against the offline dev mock API without connecting to live GAS. Never create a GAS project, bind Google Sheets, run `clasp push`/`deploy`, or request credentials to test the Base Template.
    - **Connected Projects (Live GAS Deployment Only):** Once a downstream project is connected to a real GAS deployment, verify actual GAS API response reading in a real browser via Playwright (confirming CORS, the HTTP `302` redirect to `script.googleusercontent.com`, and valid JSON rather than an HTML login/error page) before concluding live GAS integration works.

## 6. SDLC, Deployment Safety & Multi-Agent Governance (Hard Violations)

- **[OPS-1] Isolated Environments, Release Parity & Safe Rollback (ADR-0006):** Maintain exactly three environments — **Development** (offline mock), **Staging** (integration + UAT), and **Production** — with strictly distinct `scriptId`, `deploymentId`, and `SPREADSHEET_ID` enforced via `clasp -P` and `scripts/gas-deploy.mjs`. Never auto-deploy Production on merge to `main` and never store Google OAuth credentials in GitHub Actions; promote only a Release Candidate commit verified by offline CI (`quality` + `e2e`) and Staging/UAT with an explicit SemVer version and confirmation. When `main` holds unreleased features, branch urgent Production hotfixes from the latest Production release tag and merge back into `main`. Deploy immutably (`push` → `create-version` → `update-deployment`); on rollback, revert code versions immediately and **never** auto-restore Google Sheets without manual impact assessment and explicit human confirmation. Execute live Sheet schema changes via Expand–Contract with a pre-deploy Production snapshot (`docs/runbooks/deployment-and-operations.md`).
- **[OPS-2] Multi-Agent SSOT & Non-Destructive Adapters (ADR-0007):** Maintain `AGENTS.md` as the sole edited instruction file and `CLAUDE.md` strictly as a plain-text file containing `@AGENTS.md` (never a POSIX symlink). Keep `.agents/skills/` as the only committed skills directory pinned via `skills-lock.json` without floating `latest` auto-upgrades; keep `.claude/skills` gitignored and generated non-destructively via `npm run agents:setup`. Keep `.mcp.json` and `.codex/config.toml` in exact secret-free parity (never auto-mutate user `~/.gemini/config/mcp_config.json`). Run `npm run agents:check` offline inside `npm run check` and CI, treating it strictly as an automated drift gate that does not replace real verification across Antigravity, Claude Code, and OpenAI Codex CLI.

## 7. Deliberate Exceptions (Do Not Flag)

- **[EXC-1] GAS CORS Simple `POST` Requests:** Sending `POST` payloads from `frontend/` to GAS with `Content-Type: text/plain;charset=utf-8` or `application/x-www-form-urlencoded` (without unnecessary custom request headers such as `Authorization` or `X-*`) is intentional to avoid CORS preflight (`OPTIONS`), which GAS Web Apps do not support. Do not flag this as an incorrect `Content-Type` header.
- **[EXC-2] GAS Global Entrypoints & Bundle Footer:** Exporting `doGet` / `doPost` in `backend/src/main.ts` and re-exposing them as top-level global functions via `backend/build.mjs` footer (`dist/Code.js`) is required by the Apps Script V8 runtime and `@google/clasp` v3.
- **[EXC-3] Intentional Type Duplication:** Duplicating small API DTO types and canonical error codes between `frontend/` and `backend/` is acceptable when avoiding a shared build pipeline keeps GAS deployment simple, provided they remain verified by cross-workspace API contract tests (`tests/contract/api.contract.test.ts`, ADR-0001).
